#+title: Deployment

This guide installs Gnosis as a single-user systemd service. The Unix socket
and SQLite database remain local to the service account. The HTTP listener
binds to loopback by default and must not be exposed directly to an untrusted
network.

* Build and install

Install Nix, clone the repository, and build the package for the host:

#+begin_src sh
git clone REPOSITORY_URL "$HOME/src/gnosis-core"
cd "$HOME/src/gnosis-core"
nix build
nix profile install .#default
gnosisd --help
#+end_src

Install the user units and configuration:

#+begin_src sh
install -d -m 700 "$HOME/.config/gnosis" "$HOME/.config/systemd/user"
install -d -m 700 "$HOME/.local/share/gnosis/backups"
install -m 600 deployment/server.env.example \
  "$HOME/.config/gnosis/server.env"
install -m 644 deployment/gnosisd.service \
  "$HOME/.config/systemd/user/gnosisd.service"
install -m 644 deployment/gnosis-backup.service \
  "$HOME/.config/systemd/user/gnosis-backup.service"
install -m 644 deployment/gnosis-backup.timer \
  "$HOME/.config/systemd/user/gnosis-backup.timer"
systemctl --user daemon-reload
sudo loginctl enable-linger "$USER"
#+end_src

Review ~server.env~ before starting the service. Keep the database, blob root,
backup directory, and Unix socket under directories owned by the service
account.

* Import a legacy snapshot

Stop every process that can write the legacy database. Copy the database and
Notes tree into a mode ~0700~ staging directory, then record the source digest:

#+begin_src sh
STAGING_DIR=/path/to/staging
LEGACY_DB="$STAGING_DIR/gnosis-v9.sqlite"
NOTES_ROOT="$STAGING_DIR/notes"
DATA_DIR="$HOME/.local/share/gnosis"

sha256sum "$LEGACY_DB" >"$STAGING_DIR/source.sha256"
gnosisd \
  --database "$DATA_DIR/gnosis.sqlite" \
  --blob-root "$DATA_DIR/blobs" \
  --notes-root "$NOTES_ROOT" \
  --migrate-legacy "$LEGACY_DB"
sha256sum --check "$STAGING_DIR/source.sha256"
#+end_src

The importer reads the source without modifying it and refuses an existing
target. Resolve case-colliding Notes paths before retrying.

* Start and verify

#+begin_src sh
systemctl --user enable --now gnosisd.service
systemctl --user status gnosisd.service
test -S "$XDG_RUNTIME_DIR/gnosis/gnosis.sock"
curl --fail http://127.0.0.1:7842/health
#+end_src

The health response must be ~{"status":"ready"}~. It confirms a round trip
through the daemon-owned store.

Remote clients require HTTPS and per-device credentials. Keep the daemon on
loopback and place it behind a trusted authenticated proxy or private network
boundary. Create and revoke device credentials through the local Unix socket.

* Back up and validate restore

#+begin_src sh
BACKUP_DIR="$HOME/.local/share/gnosis/backups"
BACKUP_JSON=$(gnosis --socket "$XDG_RUNTIME_DIR/gnosis/gnosis.sock" \
  admin backup create --directory "$BACKUP_DIR")
BACKUP=$(printf %s "$BACKUP_JSON" | jq -r .path)
gnosis --socket "$XDG_RUNTIME_DIR/gnosis/gnosis.sock" \
  admin backup verify "$BACKUP"
gnosis --socket "$XDG_RUNTIME_DIR/gnosis/gnosis.sock" \
  admin backup restore-validate "$BACKUP" \
  --temporary-directory "$HOME/.local/share/gnosis/restore-check"
systemctl --user enable --now gnosis-backup.timer
#+end_src

The backup contains a consistent SQLite snapshot, referenced immutable blobs,
and a SHA-256 manifest. Copy verified backups to separate storage because local
retention does not protect against host loss.
